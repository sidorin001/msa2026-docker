## Балансировка и здоровье реплик

Команда: `python tests/replicas.py`. Проверено:

- 20 последовательных GET по одному HTTP-соединению строго чередуют A/B, по 10 ответов каждой. Первой может быть любая реплика. Идентификатор получен из `X-Service2-Instance`.
- Агрегирующий маршрут Service1 также распределяет 20 запросов по 10/10 через тот же Caddy, сохраняя JSON-контракт и заголовок реплики.
- Поочерёдные stop/start A и B: после активного обнаружения отказа весь новый трафик, включая агрегирование, обслуживается оставшейся репликой; восстановленная автоматически возвращается.
- Поочерёдные pause/unpause A и B: исключение по timeout readiness, работа оставшейся и возврат после успешных проверок.
- Обе реплики остановлены: Items API возвращает 502/503, агрегирование — 502/504; Groups API продолжает работать, неизвестная группа по-прежнему возвращает 404.
- Тестовый wrapper возвращает 503 только для `/ready`, оставляя Items API живым и доступным по TCP. Caddy исключает такую реплику и не возвращает её как минимум на протяжении двух дополнительных интервалов проверки без успешного readiness. После снятия отказа она снова включается в Round Robin.
- Отказ общей db2: readiness обеих реплик неуспешен, Caddy исключает обе (`no upstreams available` в новых логах); после старта db2 обе возвращаются. Seed остаётся из 10 элементов после пересоздания реплик.

Настройки проверенной конфигурации: активный GET `/ready`, строго 200, interval 5s, timeout 2s, fails 1, passes 2, `round_robin`. Passive fail_duration и retries отключены; возврат одним лишь истечением таймера не применяется. Проверки исключения/возврата используют bounded polling с deadline 30 секунд. Caddy не перезапускается при переключениях; тестовый wrapper не включён в обычный runtime-образ.

## pgAdmin и результаты

`python tests/pgadmin_browser.py` прошёл: вход через `/pgadmin/`, redirects и JS/CSS, подтверждения завершённого подключения к groups_db и items_db. Ошибок браузера нет. Снимки доступны в артефакте **browser-results** указанного запуска Actions до истечения срока хранения.

Секреты CI случайные, `.env`/`.local` не отслеживаются Git, `git diff --check` проходит. После проверки одноразовые контейнеры/volumes CI удалены.

## Границы проверки

На Windows-компьютере подготовки Docker/CMake/компилятор не установлены; локальный запуск не заявляется. Проверен указанный Linux runner; Docker Desktop/WSL, ARM, нагрузка и другие браузеры не проверялись. Общая db2 не имеет собственной репликации. До активного обнаружения фактического отказа возможны ошибки отдельных запросов; миграция уже выполняющегося запроса на другую реплику не обещается. Побитная воспроизводимость apt-пакетов не заявляется.
